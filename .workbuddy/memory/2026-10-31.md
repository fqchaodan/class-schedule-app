# 2026-10-31

## 修复：真机（Android）导入备份报「无法访问所选文件，请将备份文件复制到 Download 目录后重试」

**现象**：MuMu 模拟器导入正常，真机安装后导入失败，弹上面这句提示。

**根因**：`plus.io.chooseFile` 在 Android 上走系统文档选择器（SAF），返回的是 `content://...` URI 而不是文件路径。
- `plus.io.resolveLocalFileSystemURL(content://…)` 解析失败（原有第 1 条链路）
- `java.io.File(content://…)` 构造出的路径 `exists()` 恒为 false（原有第 2 条链路）
- 于是走到 `文件不存在` 分支，弹出 Download 提示。模拟器上大概率返回了真实路径，所以没复现。

补充事实（DCloud 分区存储适配文档 https://ask.dcloud.net.cn/article/36199）：
- `plus.io.FileReader.readAsText` **只支持应用沙盒目录**；
- 公共目录（Download 等）**只支持媒体文件**读写，json 这类非媒体文件无法用 plus.io 读。
→ 所以读用户从「下载」目录选的 json，唯一可靠路径就是 ContentResolver.openInputStream，且 SAF 授权不需要任何存储权限。

**改动**（`src/utils/file-io.ts`）：
- 新增 `readFileViaContentResolver(uri)`：Native.js 走 `runtimeMainActivity().getContentResolver().openInputStream(Uri.parse(uri))` → `InputStreamReader`+`BufferedReader` 逐行读，去 BOM；方法返回的 Java 对象必须再 `importClass` 一次才有方法代理，且 importClass 可能返回空需 `|| 原对象` 兜底。
- 新增 `stripFileScheme()`（file:// → 裸路径）。
- 新增 `readPickedFileAndroid()`：按路径形态排队重试 —— `content://` 走 ContentResolver → plus.io；其他路径走 plus.io → Native.js。`FILE_EMPTY` 视为终止态不再降级。
- `pickImportFileApp` 的 Android 分支改为调用它，并 `console.warn('[import] picked file:', filePath)` 便于真机排查路径形态。
- 错误提示拆分：FILE_EMPTY / FILE_NOT_FOUND（保留 Download 文案）/ 其他（"读取文件失败，请把备份文件放到手机「下载」目录后再试"）。

**门禁**：type-check / lint / test:run(71) 全绿。

**待办/风险**：若真机返回的仍是真实路径（而非 content://）且受分区存储限制，则需自建 SAF 选择器（`startActivityForResult` + `onActivityResult`），风险较高，等用户回传日志再定。
