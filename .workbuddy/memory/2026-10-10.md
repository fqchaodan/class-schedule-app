## 修复：微信小程序右上角胶囊遮挡自定义导航栏内容

**问题**：课表页（pages/index/index）右上角的「周/日」切换按钮在微信小程序下被原生胶囊按钮（… / ⊙）遮挡、无法点击。根因是自定义导航栏（navigationStyle: 'custom'）里标题行用 `justify-between` + `px-4` 把内容推到右边缘，而微信胶囊固定绘制在距屏幕右侧约 10px 处、覆盖宽度约 95px，任何压到该区域的页面元素一律被挡（且不可点击）。

**方案**：新建 `src/utils/platform.ts` 统一处理胶囊安全区
- `navRightInset`：ref，由 `initPlatformInsets()` 在 MP-WEIXIN 下用 `wx.getMenuButtonBoundingClientRect()` 计算 = 胶囊 left + width + 8（普通机型 375pt → 约 95，全面屏 390pt → 约 107）；API 不可用时兜底 107；非小程序端保持 0
- `navRightPadding()`：小程序返回 `${inset}px`，其余平台返回 '16px'
- `navRightLimit()`：小程序返回 `${inset}px`（供 maxWidth 限宽），其余返回 undefined

**改动文件**
1. `src/utils/platform.ts`（新增）
2. `src/pages/index/index.vue`：标题行 class 由 `px-4` 改为 `pl-4`，`:style="titleBarRightStyle"`；`titleBarRightStyle` 取「实时测量的胶囊 left」与「inset-8 估算值」的较小者作为 paddingRight（横屏/分屏更安全）；onMounted 测量 + 监听 window resize 重测，onUnmounted 卸载监听。并给 wd-segmented 加 `custom-class="!w-auto"`（wot-ui segmented 默认 width:100%，会导致 justify-between 失效、无法靠右），标题 text 改 `shrink-0` 防截断。
3. `src/components/NavBar.vue`：`px-3` → `pl-3` + 动态 paddingRight；顶部同步调用 initPlatformInsets()（避免首帧闪到胶囊下）；右侧插槽容器加 `:style="{ maxWidth: navRightLimit() }"`；顺手把 `const goBack = () =>` 改回 function 声明（antfu/top-level-function）。
4. `src/pages/stats/stats.vue`：范围切换行 `px-4` → `pl-4` + `:style="headerRightStyle"`（同样有 wd-segmented 压在胶囊下）。

**其他页面的现状**（本次未改，供后续参考）：list、templates、recycle 等页面用的是默认导航栏（pages.json 里未设 navigationStyle: custom），微信会自带标题栏，无遮挡问题；settings 页虽是自定义导航栏，但内容左对齐，同样无遮挡。

## 修复回归：加 `!w-auto` 后 segmented 上浮压住标题

**现象**（用户真机截图）：标题行里「周/日」segmented 垂直上浮，压住了「我的课表」文字，且整行错乱。

**根因**：`wd-segmented` 根元素带 unocss-preset-uni 注入的 `vertical-align: middle`。而外层容器原本只写了 `ml-2 shrink-0`（没写 flex），是普通块级容器 → 子元素按 inline-block 参与行内排版，`vertical-align: middle` 以「x-height 中线」对齐，导致控件被抬高；再叠加 `!w-auto`（宽度不再撑满）后错位就暴露出来了。

**修复**：
1. index.vue：右侧容器补 `flex items-center`（`ml-2 flex shrink-0 items-center`），走 flex 布局后 vertical-align 彻底失效；标题 text 改回 `truncate`（flex 下能正常省略），并改回内容为「我的课表」（之前调试改名成「我的课表11」）。
2. stats.vue：范围切换行的 `custom-class="!w-auto !align-middle"` 显式复位 vertical-align（该行只有 segmented 一个子元素，无需额外包裹）。

**结论**：wot-ui 组件放进 flex 行时，父容器必须显式 `flex items-center`，不能只靠 flex 父级继承。这条已并入 MEMORY.md 的胶囊安全区条目。

## 二次返工：换布局 + 修 window 报错

**仍存在的问题**（用户第二次截图）：
1. 标题行还是乱 —— 「周/日」segmented 依旧压在标题上（wot-ui 组件自身的 inline 排版在自定义导航栏里反复出问题，不值得继续抠）
2. 控制台报错 `TypeError: Cannot read property 'addEventListener' of undefined`（pages/index/index.js:127）

**报错根因**：微信小程序 appservice 里**没有 `window`**。上一轮写的 `window.addEventListener?.('resize', ...)` 用了可选调用 `?.()`，它只保护「方法不存在」，**不保护「window 本身是 undefined」** —— 于是读属性时就抛了 TypeError。正确写法是 `typeof window !== 'undefined'` 先判断。

**最终方案（换布局）**：
1. **把「周/日」切换按钮从右上角挪到左侧**，与日期导航合并成一行，右上角只留微信胶囊，遮挡问题从根上消失（不再依赖 padding 让位）。
2. **弃用 `wd-segmented`，改手写主色胶囊切换**：`flex items-center gap-0.5 rounded-lg bg-gray-100 p-0.5` 容器 + 两个 `h-7 w-9` 固定尺寸子项，激活态 `bg-indigo-500 text-white`。固定像素尺寸，不再受第三方组件 inline 排版 / `vertical-align: middle` 影响。
3. index.vue 头部结构：原来「标题行 + 日期行」两行（共 44px + 导航行）压缩为**单行 44px**：左侧 `‹ 10.5-10.11 › 今天`，右侧 `N 节` + 周/日胶囊；整行仍套 `:style="titleBarRightStyle"` 做胶囊让位兜底（现在按钮已在左侧，不影响）。
4. `src/utils/platform.ts` 新增 `hasDomWindow()`（`typeof window !== 'undefined' && typeof window.addEventListener === 'function'`）与 `measurePlatformInsets()`（可重复调用的重测函数），`initPlatformInsets()` 改为幂等 + 内部判空后注册 resize 监听。
5. index.vue 的 onMounted/onUnmounted 也改成 `typeof window !== 'undefined'` 判空写法。

**遗留**：stats.vue 的范围切换行（日/周/月/年）仍是 `wd-segmented`，本轮未动；用户未反馈该页有问题。

**校验**：eslint 全部通过；vue-tsc 对 platform.ts / index.vue 无报错。

## 三次返工：真正原因 —— 胶囊 API 的调用时机 + 改「预留区」布局

**第三次截图仍被挡**：周/日胶囊仍在标题右侧紧贴微信胶囊。

**真正根因（前两轮都没抓对）**：`wx.getMenuButtonBoundingClientRect()` **只有在页面 ready 之后调用才能拿到准确值**。我原来把 `initHeaderInsets()` 放在 `<script setup>` 顶层（模块求值期，远早于页面 ready），拿到的是异常/空值；随后 `titleBarRightStyle` 里 `segRect` 为 null 时又 fall through 到普通平台的 `16px` 兜底 —— 右侧按钮于是被推到屏幕右边缘 16px 处，正好压在胶囊下面。**两轮改动都在「padding 让位」这条思路上打转，而 padding 值本身就没算出来。**

**最终方案（结构上根除）**：
1. **把测量移到 `onMounted` + `onReady(nextTick)`**（双保险，部分机型 ready 偏早需再等一帧），顶层不再调用测量函数。
2. **改「预留区」布局，不再依赖 paddingRight**：顶部工具条 = `flex items-center`，左边 `flex-1 pl-4` 放全部内容，右边一个 `shrink-0` 的空占位块 `capsuleReserveStyle`，小程序端 `width = 胶囊 left`（约 278pt）、其余平台 `width: 0`。内容区被 flex 挤到胶囊左侧，**胶囊下方物理空置，不存在遮挡**；测量失败时兜底 200px，宁可多留白也不被挡。
3. 右上方只剩微信胶囊，头部改为两行：第一行周期导航（‹ 本周 › 今天），第二行周/日胶囊 + 「本周 N 节」。

**教训**：小程序 API 取值时机很关键，模块顶层 ≠ 页面 ready；另外「让位」类需求优先用**结构占位**（flex + 空块），比算 padding/margin 数值更不容易出错。

**校验**：eslint 通过；vue-tsc 对 index.vue 无报错。

## 微信小程序平台适配：看板横屏（降级）+ 设置导入导出（实现）

用户的诉求是「看板的横屏、设置的导入导出在微信小程序均不受支持」。两者性质不同，分别处理：

### 一、看板横屏 → 小程序端降级隐藏（能力上无法实现）

**为什么做不了**：微信小程序**不支持运行时切换屏幕方向** —— `pageOrientation` 只能在 `pages.json` 里按页面静态声明，且小程序环境没有 `screen.orientation`（H5 路径）、也没有 `plus.screen`（APP 路径）。更危险的是：`isLandscape` 是全局 ref，一旦置真会同时隐藏标题行、工具条和 tabbar，而小程序端又没有实际物理旋转 → 页面卡在「假横屏」且没有任何按钮能退出。

**改动（`src/pages/list/list.vue`）**：
1. 新增 `const canRotate = ref(true)`，`#ifdef MP` 里置 `false`。
2. 工具条里的 `rotate-right` 按钮加 `v-if="canRotate"`；右上角横屏浮动旋转按钮改为 `v-if="isLandscape && canRotate"`。小程序端两个入口都不渲染。
3. `rotateScreen()` 内 `#ifdef MP` 段：直接 toast「小程序端不支持横屏，可缩放看板」后 `return undefined`（二次保险，防止意外调用把 `isLandscape` 置真）。
4. `#ifdef MP` 段额外加 `isLandscape.value = false` 兜底复位（防历史持久化状态残留导致 tabbar 被隐藏且无法退出）。

**踩坑**：`return` 后面紧跟条件编译块时，esbuild 会因自动插入分号产生 warning（`The following expression is not returned because of an automatically-inserted semicolon`），必须写成 `return undefined`。

**小程序端的替代能力**：竖屏看板本身可用，缩放（0.5~2.0 共 8 档，`ZOOM_LEVELS`）仍有效，所以对小屏可用性影响不大。

### 二、设置页导入导出 → 真正实现小程序端支持

小程序**可以**做，只是入口与 APP/H5 完全不同：无 DOM（无 Blob/`download`/`<input type=file>`），文件系统是沙箱式。

**新增两个函数（`src/utils/file-io.ts`）**：

- `exportFileMp(data, filename): Promise<string>`
  1. `uni.getFileSystemManager().writeFile()` 写入 `${USER_DATA_PATH}/${filename}`（JSON.stringify(data, null, 2)，encoding `utf8`）
  2. 写入成功后调 `uni.shareFileMessage({ filePath, fileName })` 弹出微信分享面板 → 用户转发到「文件传输助手」/任意聊天即长期保存
  3. 用户取消分享（errMsg 含 `cancel`）**不算失败**，仍 resolve（文件已在本地）
- `pickImportFileMp(): Promise<unknown>`
  1. `uni.chooseMessageFile({ count: 1, type: 'file', extension: ['json'] })` 从聊天记录选文件
  2. `fs.readFile({ filePath: file.path, encoding: 'utf8' })` 读取 → `JSON.parse`
  3. 沿用 `settled` 标志防重复回调（与 APP 版 `pickImportFileApp` 一致的写法）

两个函数都用 `#ifndef MP → reject(new Error('仅支持小程序端'))` 兜底，保持与 APP 版对称的结构。

**`src/pages/settings/settings.vue` 改动**：`exportData()` / `pickImportFile()` 的 `#ifdef MP` 分支由原来的「暂不支持」`dialog.alert` 换成调上面两个函数（`uni.showLoading` + then/catch + toast），import 语句补上 `exportFileMp` / `pickImportFileMp`。**解析后的流程完全复用现有的 `handleImportParsed` → `validateImportFile` → `importPreview` 弹窗 → `doImport('merge'|'append')`**，无需任何改动。

**类型踩坑**：`uni.env` 在当前版本的 `@dcloudio/types` 里**没有类型声明**（`Property 'env' does not exist on type 'Uni'`）。且 `uni.env.USER_DATA_PATH` 只在 `#ifdef MP` 内有效，条件编译在本平台会把代码剔除掉，但 MP 构建时类型检查仍会看这段。解决：用 `(uni as unknown as { env?: {...} }).env?.USER_DATA_PATH ?? globalThis.wx?.env?.USER_DATA_PATH ?? ''` 双路兜底，拿不到就 reject。
（注：`uni.getFileSystemManager()` / `uni.shareFileMessage()` / `uni.chooseMessageFile()` 的类型是有的，直接 `uni.xxx` 即可，**不需要** `(uni as any)`，这次顺手把初版写的 `as any` 去掉了。）

**校验**：`npx pnpm@10 run build:mp-weixin` 构建通过（DONE Build complete），esbuild 不再有 warning；`vue-tsc` 对 list.vue / settings.vue 无新增报错（file-io.ts / notification.ts 里的 `plus.android.importClass` 构造签名报错是**改动前就存在的历史问题**，与本次无关）。顺手把 `i-carbon-renewal-import` 加进 `uno.config.ts` 的 safelist（旋转蒙层用，之前 unocss 报 `failed to load icon`）。
